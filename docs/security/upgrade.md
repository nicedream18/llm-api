# 安全规则与脱敏升级说明

## 安装及升级

本功能基于 `5a73c89`，使用独立分支 `codex/security-rules-redaction`。无需导入原工作区的其他修改。依照项目原有方式备份数据库，执行现有迁移命令或正常启动应用；只有迁移成功后才播种规则和初始化策略。未在生产数据库执行迁移。

新增迁移 027（高熵依赖）、028（自定义匹配兼容）、029（安全策略）；不修改既有迁移文件。新库使用更新后的 `docs/waliapi.sql`。存量自定义规则迁移成 `blacklist + regex`，原 `action=allow` 保持原含义，不产生白名单豁免。内置规则按 `rule_id` 补插，已有主键、名称、严重度、动作和开关保持。恢复默认值只恢复目录管理的内置规则，保留未知历史记录和自定义规则，并在同一事务中执行。

当前统一目录有 60 条规则，包含原有 41 项检测。教程 25 项行为对应见 [规则对应表](rule-coverage.md)。内置检测表达式由代码维护，数据库编辑的是策略，不能通过接口改写检测器。

## 策略语义与首次初始化

环境变量只用于首次初始化数据库中的单例策略；此后每个请求从数据库读取一次设置和规则快照，管理台修改不需要重启，其他进程的新请求也会读取新值。一次请求（包括响应阶段）始终使用同一个快照。

| 升级前模式 | 升级前 `redact_secrets` | 初始化后模式 | 独立脱敏开关 |
|---|---|---|---|
| audit / warn / block | 任意 | 保持 | 关闭 |
| redact | true | redact | 关闭 |
| redact | false | audit | 关闭 |

该映射保留旧版有效行为：旧开关仅控制 redact 模式的脱敏，不在 audit 模式强制执行。首次初始化后，用户开启“密钥自动脱敏”会启用新语义：扫描总开关开启时，即使 audit 模式、低风险或未产生 finding，仍清理已识别凭证。扫描总开关关闭则不改写上游请求。

处置顺序：有效阻断优先；然后执行命中规则的显式 redact/sanitize；独立密钥脱敏；redact 模式且整体风险为 High/Critical 时清理凭证；其余保留审计发现。`allow` 不覆盖其他阻断规则。仅当内容实际改变才记录 sanitized。日志中的凭证副本始终清理，日志副本的清理不意味着发往上游的请求发生过脱敏。

密钥和完整或不完整私钥块替换为 `[REDACTED]`；敏感 JSON 字段的短值、对象、数组整体替换。证据只保留位置、占位符和 SHA-256，不存储原始凭证。

## 管理入口及接口

React 管理台 `/admin/#/security` 提供独立安全页面：设置保存、规则筛选和编辑、恢复默认值、黑白名单 CRUD、启停、分页发现及关联请求详情。旧安全页面的策略开关也使用持久化接口。均沿用管理员认证和现有响应封装。浏览器使用的 origin 必须在项目已有 `CORS_ALLOWED_ORIGINS` 中，写操作受现有来源校验保护。

| 接口 | 用途 |
|---|---|
| GET /api/v1/security/settings | 有效设置及能力限制 |
| PUT /api/v1/security/settings | 部分设置保存，严格校验布尔值和模式 |
| GET /api/v1/security/rules/builtin | 完整目录配置，含 toggle_key |
| PUT /api/v1/security/rules/builtin/{id} | 按记录主键编辑 enabled/severity/name/description/action |
| POST /api/v1/security/rules/builtin/reset | 事务恢复受管规则默认值 |
| GET/POST /api/v1/security/rules/custom | 列表 / 创建 |
| PUT/DELETE /api/v1/security/rules/custom/{id} | 部分编辑 / 删除 |
| GET /api/v1/security/findings | 分页发现，保留原有请求关联接口 |

新建自定义规则默认 `blacklist + literal`，指定 category：domain/path/tool/keyword。白名单强制 `literal + allow`。域名按规范化主机名精确匹配；`*.example.com` 仅匹配子域，不含主域。路径规范化后按目录边界匹配（POSIX 大小写敏感、Windows 不敏感）；工具按结构化完整名称匹配且大小写敏感；关键词按忽略大小写的字面子串匹配。正则只供高级黑名单及旧记录兼容使用，需可信管理员维护；语法和常见嵌套量词校验不构成任意正则的执行时间保证。

白名单只豁免命中值及映射类别，不豁免其他值、显式黑名单、凭证或强制密钥脱敏。远程脚本执行、敏感数据外传和越权指令不会因工具白名单跳过。

## 转发范围及限制

- OpenAI Chat、Anthropic Messages、Responses、Completions 的普通和流式**请求体**都先扫描原始 JSON，再使用脱敏后的数据转换协议和发往上游。
- multipart 按原顺序扫描每一个非文件文本 part（包括重复字段），仅替换文本内容；文件字节、元信息和 boundary 保留。重复 model 字段拒绝。
- 普通响应继续扫描并按同一快照脱敏。开启普通响应扫描后，流式请求在连接上游前明确拒绝；暂不支持流式**响应**扫描和二进制附件内容扫描。
- 单个字符串超过 1,000,000 字符、嵌套深度超过 64 或结构预算超过 100,000 节点时明确报扫描错误，按 fail_closed 决定是否拒绝，不将截断结果当成成功。设置快照读取失败按启动配置的 fail_closed 处理；扫描阶段失败按本次有效快照处理。
- 规则是启发式检测，不是任意敏感数据识别器。自由文本中的无标识随机字符串不保证被识别成密钥；高熵检测是供审计的候选规则，可显式配置为脱敏或阻断。

回滚应用前备份当前策略与规则；新增字段为增量结构，不删除旧数据。旧代码不识别新增策略语义和白名单，不应将回滚视为同等安全行为。升级验收及已知基线失败见 [验证记录](verification.md)。
